## Backend / Handoff Notes
Reminders fire every 10 minutes via the `push_reminders_every_10min` pg_cron job, which calls `public.invoke_push_reminders()` (Vault-backed). The 10-minute tick is NOT the notification frequency — it exists because the matcher uses a ±5-minute window, so 10-minute ticks tile the day without gaps. Most ticks send nothing.

Timezone: ALL matching is done in Africa/Lagos via `getLagosDateParts()`, deliberately NOT server-local or browser-local time — edge functions run UTC and the users do not. Activity times are stored as 24h strings (`parseTime` also handles "6:00 AM" forms). Intervals are resolved into a day carry (`total = nowMinutes + interval`, `carry = floor(total/1440)`, `targetMinutes = total % 1440`) so 1440 means "same slot tomorrow" and intervals crossing midnight land on the right weekday.

Current week is derived from `Cohort.startDate` using the Sunday-10am rule from weekFocus.ts, clamped to the cohort's real week range. Cohorts with a NULL startDate are skipped (they would otherwise pin to week 1 forever).

Vault prerequisites (already created in production, needed if rebuilding): secrets `project_url` and `push_reminders_service_key`.

Rollback: `select cron.unschedule('push_reminders_every_10min');` — stops all reminder traffic instantly, no redeploy.
