How the FOF API works

One secure door that lets other church apps ask FOF about people, groups, the schedule and more. Each app gets its own key, sees only what it is allowed to, and can be switched off at any time.

Live now One key per app Teens protected Next: register from the church app
Plain words

Six words to know

API
A secure doorway that lets one app ask another a question, such as "is this person in FOF?", without seeing everything inside it.
Key
A secret password for an app, not a person. Each connected app has its own. Without it, the door stays shut.
Permission
What a key is allowed to ask, such as "look people up" or "read the planner". Developers call these scopes.
Request
One question an app asks, such as "who is in Cohort 10?". Every request is recorded.
Teen permission
A separate permission. Without it, teenagers show as name and cohort only.
Handshake
The short back-and-forth when someone registers for FOF from the church app. Coming next.
The big picture

From the church app to FOF and back

Church apps never touch FOF's database. Every question goes through one door that checks four things before it answers.

What a church app can ask

Ten permissions, each switched on one at a time

An app gets only the permissions it needs. These cover what participants, supports and admins see in the FOF app.

One request, step by step

What happens when an app asks a question

  1. The app asks

    For example: "who is in Cohort 10?", with its key attached.

    Church app

  2. Key checked

    Unknown or switched-off keys are turned away.

    401 if not

  3. Permission checked

    The key must be allowed to ask this question.

    403 if not

  4. Limit checked

    Up to 60 questions a minute per app.

    429 if over

  5. Answered

    Only the agreed details, teens restricted unless allowed.

    200

  6. Recorded

    Which app, what it asked, when, and how many teens it saw. Never the answer.

    Always

For developers

Getting started

  1. Read the docs. Every address, with examples you can try: fof.tcnikorodu.org/api-docs.html
  2. Ask for a key with only the permissions your app needs. Keep it on your server.
  3. Send it with every request as Authorization: Bearer fof_live_…
  4. Use current for the running cohort, or a cohort id.
Example
curl "https://…supabase.co/functions/v1/public-api/v1/people/lookup?phone=08031234567" \
  -H "Authorization: Bearer $FOF_API_KEY"
