# Schedule and checklist as one list; tasks with deadlines and rest weeks

Date: 2026-10-24. One live migration; no edge function. FLOW_MAP rule 104 (and a pointer in rule 21).

## Summary
- **Support Schedule is one list.** Activities (set by admin, with a time) and tasks (with a deadline) sit on the same day cards. Filter chips All / Activities / Tasks replace the two tabs; Today / Tomorrow / Full week and the day strip are unchanged and now count open tasks too. Tasks with no day appear under "Anytime this week". Tasks from admin carry the quiet "From admin" tag; a support's own tasks carry nothing. A deadline shows "Due today" (orange) or "Was due ..." (red).
- **Add task** (header button on the support Schedule): a task and an optional deadline (Today, Tomorrow, a date, none). "Edit my tasks" removes the support's own tasks only. Home's box is now "Your tasks" and lists the same items.
- **Rest weeks.** The 3 weeks after a cohort have no class week, so tasks there carry only a date. The week picker gets a "Rest weeks" entry (shown when there are such tasks, or once the last class week is over), and the page opens on it automatically after the last class when tasks wait there. Three groups, Rest week 1 to 3, plus "Other dates".
- **Admin: Schedule > ⋮ > Add task for supports.** The old pop-up gained **Rest weeks** (pick Rest 1 to 3; due on each week's last day) and a new audience **Group leaders** (supports who lead an unarchived group in that cohort), next to Everyone, a tag and Choose people. "Already added" lists the rest-week tasks with who has done them.

## Live changes (applied through the Management API)
- `20261024140000_support_tasks_deadlines.sql`: `SupportChecklistItem."weekId"` now optional, new `"dueDate"` and `"cohortId"` (a week-less task needs both), unique and lookup indexes for week-less rows, the admin-task guard also locks `dueDate`/`cohortId`, new `admin_add_support_task` (class weeks and/or dates, targets ALL/TAG/USERS/LEADERS, one bell alert per support) and `admin_rest_tasks`. The old `admin_add_checklist_task` is left in place, unused by the app. Rollback lines are at the top of the file.
- No edge function was deployed or changed.

## Code review (two commits since the speed work)
Review found and these were fixed before pushing: the bell alert for a rest-week task did not open the Rest weeks view (now `&rest=1`, set in the migration, re-applied live; the alert also says "N dates, first due ..." when a task has several); a task added for a date inside another class week vanished from the view (now filed there and the page says where); the admin pop-up reset to class weeks after adding a rest-week task and showed repeated rows for a task with several dates (keys now include the date, mode is kept); Add task could save with no week and no deadline (guarded and the button is disabled without a week); the rest-week sheet could open on a past date (Today/Tomorrow hidden there, earliest date is the next rest week); the "already on your list" message now says "in this week"; the Home and Schedule date maths is one helper (`scheduleWindow`); and the Inspirational counts re-read the server after a tap so a test or practice account's tap is not counted on screen.

## Decisions and why
- Activities stay separate from tasks: they carry time, labels, the admin completion overview and the "Any notes?" popup. Only the tasks were merged into the Schedule.
- Rest-week dates are computed from the cohort (end date, else a spare week after the last class) exactly as the Planner does, and fixed on the tasks when added. If the Planner later moves the cohort's end, tasks already added keep their dates.
- Left out of the mock-up on purpose: the "Remind me the day before" push (needs a `push-reminders` change) and a free-text note on a new task. A floating Add task button became a header button.

Nothing remained afterwards (0 rows, 0 bells).

As an admin: the pop-up on Rest weeks, picking Rest 1 and 2 sent dates 27 Dec and 3 Jan with no week ids. No console errors.

## Open items
- Old per-week checklist items still show on their week as before; there is no "Past weeks" list.
- A bell alert for a task due soon does not exist (no reminders for tasks).
- A support who has tasks only in a rest week sees them only through the "Rest weeks" picker entry (or Home).

## Addendum: unfinished tasks carry over
A task not finished in an earlier week now shows in the week that is happening now, under "Carried over" ("Carried over from Week N" tag), on the Schedule (All and Tasks, Today and Full week) and on Home's Today card. In the Rest weeks view the open class-week tasks show at the top. A dated task whose date has passed also carries into the current week. Ticking it ticks the original row, so admins still see it done against its own week. It works for admin tasks and a support's own, and nothing moves in the database: `getForSchedule` just also asks for the still-open tasks of earlier weeks (`weekId.in(...)` and `done = false`). "The week happening now" is the week the app opens on (a class week turns over on Sunday at 10 am), not the calendar week. No way yet to carry a task into a later week that is not the current one, or to move a task to a chosen week (admin tasks are locked from moving anyway).
Tested in a mocked browser (support login); not with a real login.

## Addendum (25-27 Oct): tasks do not depend on the week picker
A support added a task while the Schedule showed Week 1; its date (Sunday 25 Oct) put it in Week 2, so it disappeared from the list they were looking at. The week picker no longer touches tasks. The Schedule and Home load every task the support has in the cohort in one query (`supportChecklistApi.getForCohort`, which replaces `getForSchedule`) and list them by when they are due: Overdue, Today, Coming up, No deadline, in one "Your tasks" block. Week, Today/Tomorrow/Full week and the day strip only change the activities. An older admin task that only names a weekday is given a date from its class week (`effectiveDue`), so a missed one shows as overdue. An open task from an earlier class week keeps showing, tagged "Carried over from Week N", so the separate "Carried over" group, the "tasks on other days" line, the "Anytime this week" card and the "filed in Week N" notice are gone. FLOW_MAP rule 104 is updated. Tested in a mocked browser: the same tasks appear on the default week and on Week 5, and a new task shows at once. Not tried with a real login (the real account that hit this has the task saved correctly in the database).

Code review of this batch (fixed before pushing): the Home badge counts activities today plus open tasks due today or overdue (it counted every open task); Home loads tasks as long as there is a cohort (it was gated on a week being loaded); ticked tasks sit in their own muted "Done" group instead of under the red Overdue heading; Home and Schedule use the same "week now" for the "Carried over from Week N" tag; the loading line shows once and the empty line no longer flashes first; the Rest weeks leftovers are headed "Other tasks"; the attendance "last class" button follows the date. Left as designed: tapping a day in the strip changes only the activities, not the tasks (the point of this change).
