# FOF public API 1.1: what people see in the app, teens protected

Date: 2026-10-29. FLOW_MAP rule 118 (rewritten). Docs: `docs/api/README.md`, `/api-docs.html`.

## Why
Owner: church apps should be able to pull anything participants, supports or admins see, request photos and
birthday pictures, and see the planner, with teenagers protected. Owner's choices:
- teens behind a separate `teens:read` permission;
- reflections, notes, private messages and who gave anonymous feedback stay private;
- birthdays as both data and a finished picture.

## What changed
- Migration `20261029140000_public_api_v1_1.sql`, **applied live**:
  - New `api_*` functions: full profile, cohort participants (paged), attendance, programme (teen-aware), faith
    project, team, groups, hubs, class weeks, weekly schedule, planner inputs, opened scriptures, announcements,
    resources, birthdays, birthday person.
  - Helpers: `api_is_teen` (teen age range or an unarchived teen group), `api_cohort_id` ("current" or an id).
  - `ApiRequestLog."teenRecords"`: how many teen records each answer showed in full.
  - New scopes in `api_create_client`. The lookup now says `isTeen`.
- Edge function `public-api`, **deployed live (version 4)**:
  - New routes; the full list is in `docs/api/README.md`.
  - `planner.ts`: a port of the app's `buildPlannerCohorts`. Keep the two in step.
  - `birthday.ts`: the birthday PNG via og_edge (Satori + resvg), with Montserrat TTFs (OFL) in `fonts/`.
- `openapi.json` is 1.1.0. The Scalar page draws the new addresses from it.

## Teens
- Without `teens:read`, a teen is id, name, cohort and `restricted: true` everywhere:
  - attendance, programme and faith project come back restricted;
  - birthdays leave teens out;
  - a teen's birthday picture is refused.
- With `teens:read`: full profile plus guardian name and phone.
- To see which apps looked at teens: the SQL in `docs/api/README.md`.

## Code review (/code-review medium), all fixed before going live
- Audit missed teen views on attendance, programme and faith project: those answers now carry `isTeen`.
- Birthdays leaked restricted teens' birth dates: teens are now left out without `teens:read`.
- Broken key-issuing SQL in the README.
- Schedule days were in id order: now Sunday to Saturday, like the Schedule page.
- The planner used its own test-cohort rule: now `api_real_cohort`.
- Birthday PNG errors could arrive as a broken 200: the picture is now fully drawn before answering.
- Avatar fetch could reach any URL: now only this project's storage, no redirects.
- Archived teen groups made adults look like teens.
- Impossible `until` dates were accepted.

## Tested live
Two temporary keys: one with every scope except `teens:read`, one with `people:read`, `teens:read` and
`birthdays:read`. Both keys and their 31 log rows were deleted afterwards, so no keys exist.

Checks and results:
- Profile, adult: all fields.
- Profile, teen without `teens:read`: restricted. With `teens:read`: includes guardian.
- Attendance (10 weeks), programme, faith project: 200.
- Participants: 87, with 18 restricted. With `teens:read`: 0 restricted.
- Team 49, groups 28, hubs 6, weeks 10, schedule 10.
- Planner: Cohort 9 and Cohort 10, then planned Cohort 11 and Cohort 12 with phases.
- Content: 20 scriptures, 31 announcements, 8 resources.
- Birthdays over 366 days: 74 with no teens without `teens:read`; 75 including 1 teen with it.
- Birthday picture: PNG, about 2 to 3 seconds.
- Errors: a bad `until` date gives 400, a bad cohort 404, a missing scope 403.
- Audit: `teenRecords` came back as 1, 18 and 1 on the teen key's requests.

The first deploy of the picture hit Supabase's compute limit (546). Removing the blurred shadows and one font
brought it under; shadows are now flat translucent shapes.
